# 登录验证拦截器使用说明

## 功能说明

已实现全局登录验证拦截器，**未登录用户无法访问任何模块的数据接口**。

## 实现文件

1. **LoginInterceptor.java** - 登录拦截器
   - 位置：`src/main/java/com/yq/spbYq/util/LoginInterceptor.java`
   - 功能：检查每个请求的Session中是否有userId

2. **WebMvcConfig.java** - 拦截器配置
   - 位置：`src/main/java/com/yq/spbYq/WebMvcConfig.java`
   - 功能：配置拦截规则和放行规则

## 拦截规则

### ✅ 已登录用户可以访问
- 所有数据查询接口（queryByPage, queryById等）
- 所有数据操作接口（add, edit, delete等）
- 所有业务模块接口

### ❌ 未登录用户无法访问
- 所有 `/spbYq/*` 下的数据接口都会返回 **401 错误**
- 响应内容：`{"code":0,"msg":"请先登录"}`

### ⭕ 无需登录即可访问（已放行）
1. **登录注册相关**
   - `/users/login` - 登录接口
   - `/users/add` - 注册接口
   - `/users/register` - 注册接口（备用）
   - `/users/logout` - 登出接口

2. **静态资源**
   - 所有 `.html` 页面
   - 所有 `.css` 样式文件
   - 所有 `.js` 脚本文件
   - 所有图片文件（.png, .jpg, .jpeg, .gif, .ico）
   - 所有字体文件（.woff, .woff2, .ttf, .eot, .svg）

3. **系统页面**
   - `/error` - 错误页面

## 使用方式

### 1. 重启应用
```bash
# 停止当前运行的应用
Stop-Process -Name java -Force

# 重新启动
.\mvnw.cmd spring-boot:run
```

### 2. 测试登录拦截

**未登录时访问数据接口：**
```javascript
// 浏览器控制台测试
fetch('http://localhost:8081/spbYq/healthRecords/queryByPage?page=1&size=10')
  .then(res => console.log('状态码:', res.status))  // 401
  .then(res => res.json())
  .then(data => console.log('响应:', data));  // {code: 0, msg: "请先登录"}
```

**登录后访问：**
1. 先访问 `login.html` 进行登录
2. 登录成功后，Session会保存 userId 和 userType
3. 此时可以正常访问所有数据接口

### 3. 前端处理建议

在每个页面的JavaScript中添加401错误处理：

```javascript
fetch(url)
  .then(res => {
    if (res.status === 401) {
      // 未登录，跳转到登录页
      alert('请先登录');
      window.location.href = 'login.html';
      return;
    }
    return res.json();
  })
  .then(data => {
    // 正常处理数据
  });
```

## Session机制说明

### 登录成功后保存的信息
```java
// UsersController.java - login方法
request.getSession().setAttribute("userType", user.getUserType());
request.getSession().setAttribute("userId", user.getUserId());
```

### 拦截器检查的内容
```java
// LoginInterceptor.java
HttpSession session = request.getSession(false);
if (session == null || session.getAttribute("userId") == null) {
    // 未登录，返回401
}
```

## 注意事项

1. **静态资源已放行** - 用户可以直接访问 HTML 页面，但页面中的数据请求会被拦截
2. **登录页面必须放行** - 否则会出现死循环（无法登录）
3. **Session超时** - 默认30分钟无操作Session会失效，需要重新登录
4. **跨域配置** - 已在 CORSConfiguration 中配置允许携带Cookie

## 修改Session超时时间

如果需要修改Session超时时间，在 `application.properties` 中添加：

```properties
# 设置Session超时时间为60分钟（默认30分钟）
server.servlet.session.timeout=60m
```

## 安全建议

1. ✅ 生产环境建议使用 HTTPS
2. ✅ 敏感操作（删除、修改密码等）建议二次验证
3. ✅ 可以添加登录失败次数限制，防止暴力破解
4. ✅ 定期清理过期Session
