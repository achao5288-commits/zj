# 用户管理模块权限控制说明

## 功能说明

已实现用户管理模块的权限控制，**普通用户无法看到和访问用户管理模块**，只有 root 用户（管理员）才能使用。

## 权限级别说明

- **userType = 1**：普通用户
- **userType = 2**：root 用户（管理员）

## 实现方式

### 1. 前端控制（隐藏模块卡片）

**文件**: `src/main/webapp/index.html`

**修改内容**:
```html
<!-- 用户管理模块 - 仅root用户可见 -->
<div class="col-md-4" id="userManagementModule" style="display:none;">
    <!-- 模块内容 -->
</div>
```

**JavaScript 逻辑**:
```javascript
// 根据用户类型显示/隐藏用户管理模块
if (user.userType == 2) {
    // root用户，显示用户管理模块
    document.getElementById('userManagementModule').style.display = '';
} else {
    // 普通用户，隐藏用户管理模块
    document.getElementById('userManagementModule').style.display = 'none';
}
```

### 2. 后端控制（API 权限校验）

**文件**: `src/main/java/com/yq/spbYq/controller/UsersController.java`

**受保护的接口**:

#### ✅ queryByPage - 查询用户列表
```java
@RequestMapping("queryByPage")
public ReturnVO queryByPage(HttpServletRequest request, ...) {
    // 权限校验：只有root用户可以查看用户列表
    if (!isRootUser(request)) {
        return ReturnVO.error("无权限操作，仅管理员可查看用户管理");
    }
    // ... 查询逻辑
}
```

#### ✅ queryById - 查询用户详情
```java
@RequestMapping("queryById/{id}")
public ReturnVO queryById(HttpServletRequest request, @PathVariable("id") Integer id) {
    // 权限校验：只有root用户可以查看用户详情

        return ReturnVO.error("无权限操作，仅管理员可查看用户信息");
    }
    // ... 查询逻辑
}
```

#### ✅ edit - 编辑用户（已有权限控制）
```java
@RequestMapping("edit")

```

#### ✅ deleteById - 删除用户（已有权限控制）

#### ⭕ add - 注册用户（无需权限控制）
```java

    // ... 注册逻辑

```

## 权限控制矩阵

| 接口 | 普通用户 (userType=1) | Root用户 (userType=2) | 说明 |
|------|---------------------|---------------------|------|
| `/users/queryByPage` | ❌ 禁止访问 | ✅ 允许访问 | 查看用户列表 |
| `/users/queryById/{id}` | ❌ 禁止访问 | ✅ 允许访问 | 查看用户详情 |
| `/users/add` | ✅ 允许访问 | ✅ 允许访问 | 注册新用户 |
| `/users/edit` | ❌ 禁止访问 | ✅ 允许访问 | 编辑用户信息 |
| `/users/deleteById/{id}` | ❌ 禁止访问 | ✅ 允许访问 | 删除用户 |
| `/users/login` | ✅ 允许访问 | ✅ 允许访问 | 登录接口 |

## 安全机制

### 双重保护

1. **前端隐藏** - 普通用户在界面上看不到用户管理模块
2. **后端校验** - 即使普通用户直接调用API，也会被拒绝

### 权限校验方法

```java
private boolean isRootUser(HttpServletRequest request) {
    Object userTypeObj = request.getSession().getAttribute("userType");
    return userTypeObj != null && userTypeObj.equals(2);
}
```

**工作原理**:
- 从 Session 中获取 `userType`
- 检查是否等于 2（root用户）
- 返回 true/false 决定是否放行

## 注意事项

1. ✅ **Session 必须存在** - 用户必须先登录才能访问
2. ✅ **前端+后端双重验证** - 提高安全性
3. ✅ **注册接口放行** - 允许新用户注册
4. ✅ **登录接口放行** - 允许用户登录
5. ⚠️ **不要删除后端的权限校验** - 前端控制可以被绕过

## 扩展建议

如果需要更细粒度的权限控制，可以考虑：

1. **基于角色的访问控制 (RBAC)**
   - 创建角色表（role）
   - 创建用户-角色关联表（user_role）
   - 创建权限表（permission）
   - 创建角色-权限关联表（role_permission）

2. **使用 Spring Security 或 Apache Shiro**
   - 更强大的权限管理框架
   - 支持注解式权限控制
   - 支持更复杂的权限规则

3. **操作日志记录**
   - 记录所有用户管理操作
   - 便于审计和追踪
