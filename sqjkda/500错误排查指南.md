# 500错误排查指南

## 问题描述
点击"验证并添加"后，后端返回 500 Internal Server Error

## 已修复的问题

### ✅ 添加了异常处理
现在 `addDeviceBySdk` 方法包含了完整的 try-catch 块，会捕获并返回详细的错误信息。

### ✅ 添加了日志输出
- 异常信息会打印到控制台
- 设备同步成功/失败都会有日志

---

## 🔍 排查步骤

### 步骤1：查看后端控制台

重启后端服务后，再次尝试添加设备，查看控制台输出：

**可能的错误信息：**

#### 错误1：数据库表不存在
```
Table 'xxx.health_devices' doesn't exist
```
**解决方案：**
```sql
-- 执行建表脚本
source C:\Users\Hp\Desktop\软著\sqjkda\src\main\resources\health_monitoring_setup.sql
```

#### 错误2：数据库连接失败
```
Communications link failure
```
**解决方案：**
1. 检查 MySQL 是否启动
2. 检查 `application.properties` 中的数据库配置

#### 错误3：字段不匹配
```
Unknown column 'xxx' in 'field list'
```
**解决方案：**
检查数据库表结构是否与实体类匹配

#### 错误4：Session相关
```
Cannot invoke "Object.equals(Object)" because "userTypeObj" is null
```
**解决方案：**
确保用户已正确登录

---

### 步骤2：检查数据库表是否存在

在 MySQL 中执行：
```sql
USE your_database_name;
SHOW TABLES LIKE 'health_devices';
SHOW TABLES LIKE 'health_monitoring_data';
```

如果表不存在，执行建表脚本：
```bash
mysql -u root -p your_database_name < src/main/resources/health_monitoring_setup.sql
```

---

### 步骤3：检查数据库表结构

```sql
DESC health_devices;
```

应该包含以下字段：
- device_id (INT, AUTO_INCREMENT)
- user_id (INT)
- device_name (VARCHAR)
- device_type (VARCHAR)
- device_brand (VARCHAR)
- device_model (VARCHAR)
- device_sn (VARCHAR)
- connection_type (VARCHAR)
- is_active (TINYINT)
- last_sync_time (DATETIME)
- bind_time (DATETIME)
- status (VARCHAR)
- create_time (DATETIME)
- update_time (DATETIME)

---

### 步骤4：检查数据库配置

查看 `src/main/resources/application.properties`：

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/your_database?useSSL=false&serverTimezone=UTC
spring.datasource.username=root
spring.datasource.password=your_password
```

确保：
- 数据库名称正确
- 用户名密码正确
- MySQL 服务已启动

---

### 步骤5：手动测试数据库插入

在 MySQL 中手动插入一条测试数据：

```sql
INSERT INTO health_devices (user_id, device_name, device_type, device_brand, device_model, 
                            device_sn, connection_type, is_active, status)
VALUES (32, '测试手环', '智能手环', '小米', 'MI-BAND-7', 
        'MI-BAND-SDK-2024', 'Bluetooth', 1, 'online');
```

如果插入失败，说明表结构或数据库有问题。

---

### 步骤6：检查用户登录状态

确保：
1. 用户已登录
2. Session 中包含 `userId` 属性
3. 用户可以访问该页面

在浏览器控制台检查：
```javascript
console.log(localStorage.getItem('userInfo'));
```

## 📋 常见解决方案

### 方案1：重新导入数据库表

```bash
# 1. 备份数据（如果需要）
mysqldump -u root -p your_database health_devices > backup.sql

# 2. 删除旧表
mysql -u root -p your_database -e "DROP TABLE IF EXISTS health_devices;"

# 3. 重新创建
mysql -u root -p your_database < src/main/resources/health_monitoring_setup.sql
```

### 方案2：清理并重启

```bash
# 1. 停止项目
# 2. 清理编译
mvn clean
# 3. 重新编译
mvn compile
# 4. 重启
mvn spring-boot:run
```

### 方案3：检查端口

确保后端运行在正确的端口：
- 配置文件中的端口：`server.port=8080` 或 `8081`
- 前端请求的端口要匹配

从错误信息看，前端请求的是 `localhost:8081`，确保后端确实在 8081 端口运行。

## 💡 提示

- 500错误通常是后端代码或数据库问题
- 查看后端控制台是最重要的排查步骤
- 确保数据库表已正确创建
- 确保用户已登录且有正确的权限
